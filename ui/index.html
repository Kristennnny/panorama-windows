Connect Claude Code and Codex

These adapters observe agent events. They never approve tools, send replies, or read conversation transcript files.

  1. Keep this dashboard's terminal running.
  2. From the extracted Panorama folder, run:
node setup-hooks.cjs

This merges the observer hooks into your user settings and makes backups first. Keep Panorama in this location after setup.

  1. Restart Claude Code and Codex in VS Code.
  2. Review and trust the new hooks in Codex's Hooks settings or /hooks if that interface is available.
  3. Send each agent a harmless prompt that reads a local file. Its session should appear here.
  4. Open the session card and link the correct VS Code window.

Use current agent versions with lifecycle-hook support. If hooks are disabled by your organization, this starter cannot enable them. On older Codex builds the completion-only notify setting is not equivalent to input-request detection. Native Windows processes are the supported target here; WSL and remote hosts need a separate bridge.

What each signal means

Working: a prompt or tool activity was observed. After 10 minutes without another event, the card says “No recent signal” rather than inferring a decision request.

Input needed: a structured question or supported Claude notification was observed. Questions written only in the final message appear as “Ready”; they are not automatically classified.

Approval requested: an approval check began. Another hook or policy can still resolve it. A later tool event clears it; native pop-ups wait briefly to avoid most quick auto-resolutions.

Ready: a response finished. Review its excerpt or open the app.

Possible reply needed: the latest readable Claude app response ends in a question. This is a heuristic, not a confirmed request.

Claude app: its visible accessibility controls are monitored automatically. Hidden chats and minimized windows may be unreadable.

Window only: a manually tracked desktop window. Progress is not inferred from its appearance.

Windows preferences

Reads visible accessibility controls locally. Detects generation and explicit input prompts; questions in the latest readable assistant message get a “Possible reply needed” alert. Hidden chats and minimized windows cannot be monitored reliably. Unknown means the required controls were not exposed.

Pop-ups work while the local server is running, even if this page is closed. Windows Do not disturb or notification settings can suppress them. Clicking a pop-up opens the linked window, or the dashboard if no window is linked. Turn-completion events are shown here without a native pop-up.

Previews use a best-effort Windows capture method. GPU-rendered apps may produce blank images; minimized windows need restoring. This starter does not use OCR or send images to a model.
